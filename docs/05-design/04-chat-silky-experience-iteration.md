# 聊天丝滑体验迭代清单

适用范围：聊天主路径、AI 回复气泡、长任务运行态、终端输出与回到底部交互。

目标是在不偏离 DevNexus 低噪、工具化设计规范的前提下，让聊天过程具备稳定、可感知、可继续的丝滑体验。

## 体验基线

1. 发送消息后，消息列表必须自动回到最新消息。
2. AI 回复流式输出必须保留最新尾帧，不能停在前几个字。
3. 流式 Markdown 渲染要保持节流，但不能丢弃最新内容。
4. 程序自动滚动不能被误判为用户手动上滚。
5. 用户主动上滚查看历史时，系统必须尊重阅读位置。
6. 用户点击“回到最新”后，后续流式内容应恢复自动跟随。
7. 长任务和终端输出必须与聊天主线低噪联动。

## 闭环验收记录

1. 发送、编辑重发、重新生成后都调用 `MessageList.ScrollToBottomAsync(true)`，列表立即进入自动跟随窗口。
2. `ThrottledMarkdownRenderer` 保留最新 `_pendingStreamingContent`，节流窗口结束后补尾帧，避免只渲染前几个字。
3. `StreamingMarkdownFramePolicy` 固化大段 delta 的小帧渐进策略，单测覆盖小 delta 直出、大 delta 分帧和内容重写直出。
4. `scrollToBottomWhileStable` 会在 DOM 高度稳定前持续贴底，覆盖代码块、列表、终端摘要等高度变化。
5. 同一滚动容器只保留一个稳定贴底 RAF 循环，新请求会取消旧循环，避免长任务期间多个自动滚动循环叠加抢主线程。
6. 自动滚动租约用于区分程序滚动和用户上滚，避免误弹未读按钮。
7. 用户离底并且不在自动滚动租约内时，`_userScrolledAway` 会关闭自动跟随。
8. “回到最新”强制滚动后会重置未读数、恢复 `_autoFollowLatestMessage`。
9. 会话切换和历史恢复使用 `_needsScrollToBottom`，加载完成后定位最新。
10. 普通文本由尾帧渲染和 50ms 默认节流共同控制，减少批量闪现。
11. 参考 Open WebUI 的 large delta chunking 思路，前端对 provider 一次性推来的大段累计内容做小帧渐进显示。
12. 正文 `TextDelta` 不参与 live block 入场动画，只让图表、工具、通知等结构块轻量 reveal。
13. 流式 Markdown 增加 `silky-markdown-content--streaming`，首尾块间距和段落最小高度降低闭合抖动。
14. 纯文本流式正文走 text-node 快路径，不触发 `markdown-it.render` 和 DOM morph；一旦出现 Markdown 语法再回退到完整解析链路。
15. 流式结束即使内容相同，也必须从 streaming 状态收敛到最终 Markdown/enhance 状态，避免快路径文本节点残留。
16. 流式阶段跳过 `enhance`，代码高亮和按钮增强只在最终态执行。
17. 普通单 Agent 只在无内容时显示状态胶囊，正文出现后退场，避免 Thinking/正文重复闪烁。
18. Swarm 状态保留轻量跳转入口，主消息区继续承载真实对话内容。
19. 终端摘要卡片固定最小高度并关闭 scroll anchoring，减少摘要更新造成的阅读位移。
20. 终端详情面板已具备独立自动跟随、手动阅读锁定和稳定贴底逻辑。
21. 参考 Windows Terminal dirty rows 与 WezTerm viewport range 的源码思路，实时终端只渲染尾部视口，避免长输出把完整 scrollback 压进 DOM。
22. 等待 stdin 通过终端概览和挂起交互面板表达，避免主消息区重复刷状态。
23. 取消生成和终端停止在前端先做 optimistic 收敛，再等待后端回包修正。
24. 现有消息操作保留重新生成、截断续写、查看终端详情和 Swarm 详情入口。
25. 窄屏下消息列表预留底部空间，回到底部按钮限制宽度并省略长文案。
26. 流式状态区域使用 `aria-live="polite"` 与 `aria-atomic="false"`，自动滚动不主动抢焦点。
27. 当前代码已通过 `dotnet build src/client/DevNexus.Client.Web/DevNexus.Client.Web.csproj --no-restore -p:UseSharedCompilation=false -nr:false`，本地 Web 客户端 `http://localhost:5146` 返回 200 OK。
28. `StreamingMarkdownFramePolicyTests` 通过 3/3，覆盖 AI 回复气泡“持续出现、不丢尾帧”的核心纯逻辑。
29. `TerminalLiveOutputViewportPolicyTests` 通过 3/3，覆盖终端长输出尾部视口、短输出直出和空输出收敛。
30. `silkyMarkdown.fastpath.test.js` 验证纯文本流式追加、Markdown 回退和 streaming -> final 同内容重渲染。
31. `devnexus.core.scroll.test.js` 验证稳定贴底循环的取消、收敛和清理。
32. Chrome DevTools Protocol 页面级探测确认 Shared 静态资源已加载，稳定贴底 helper 可用，流式纯文本保持单文本节点追加，最终态能重新渲染收敛。

## 当前实现约束

1. 聊天主路径优先使用 `MessageList` 的滚动状态，不把滚动策略散落到消息子组件。
2. 流式 Markdown 由 `ThrottledMarkdownRenderer` 负责保留最新内容尾帧。
3. JS 滚动 helper 只做 DOM 高度稳定追踪，不承载业务状态。
4. 所有后续迭代必须继续遵守低噪、工具化、浅色工作区的现有设计规范。
