# DevNexus AI 语义文档摄取链路

## 1. 文档目的

本文档描述当前项目中“文件如何被转化为可供模型理解的语义派生物”。

它只覆盖以下能力：

- 文本抽取
- 结构摘要
- 分块
- 检索与向量化前处理
- 失败状态与降级策略

它不覆盖以下能力：

- 真实文件转换
- Excel 模板套用
- 文件工作区执行
- 外部 Python / CLI 调度
- 输出文件交付

上述能力已经转移到统一文件资产平台和文件运行时文档中。

## 2. 当前摄取主链路

当前主链路：

1. 用户上传文件
2. 平台创建 UploadSession
3. 文件完成落库后登记 FileAsset / FileVersion
4. 派生处理器根据文件类型提取语义内容
5. 生成 SmartDocument
6. 进行摘要、分块、索引或向量化
7. 将结果用于聊天引用、RAG、搜索和上下文构建

## 3. 分层职责

### 3.1 平台层负责

- 上传与校验
- 文件存储
- 版本管理
- 权限与租户隔离
- 文件任务与工作区

### 3.2 语义摄取层负责

- 读取资产内容
- 选择合适的提取策略
- 输出统一 SmartDocument
- 记录提取状态与失败原因

### 3.3 应用层负责

- 将可用的 SmartDocument 注入聊天上下文
- 触发向量化或索引
- 决定哪些文档参与引用、检索或摘要
- 依据 ChatRequest 控制上下文策略：
  - `artifactIds` 作为当前请求的活跃文档集合，优先全文注入。
  - `enableRag=true` 时允许知识库检索与文档索引补充。
  - `enableRag=false` 时仅注入活跃文档，不进行知识库检索。

## 4. 文件类型处理

### 文本类

- 直接抽取可读文本
- 保留标题和段落边界
- 必要时转为 Markdown 友好格式

### 表格类

- 提取表头、样例数据、统计摘要
- 生成适合模型阅读的紧凑文本表示
- 不在这一层进行模板映射和结果生成

### 图片 / PDF

- 先尝试低成本文本提取
- 复杂布局再进入 OCR / Vision 派生
- 失败时记录失败原因与降级路径

### 代码类

- 保留原始文本
- 提取语言、文件结构和基础统计信息
- 为代码检索和上下文压缩服务

## 5. 失败与降级

语义摄取必须是可见且可恢复的。

至少需要做到：

- 失败原因进入文档状态
- 前端可以就近展示失败摘要
- 文件即使语义失败，也不应影响其作为 FileAsset 继续参与文件运行时

输入区、放大输入框和附件 chip 都应围绕这类状态反馈保持一致。

## 6. 与文件运行时的协作关系

语义摄取与文件运行时不是二选一关系，而是并行协作关系：

- 语义层回答“模型能读到什么”。
- 文件运行时回答“系统能真实操作什么”。

同一个文件可以同时具备：

- 可引用语义上下文
- 可执行文件上下文

也可能只具备其中之一。例如：

- 某个回挂结果资产只进入执行上下文，不进入语义上下文。
- 某个解析失败文件不进入语义上下文，但仍然保留资产事实和失败原因。

## 7. 当前关键边界

- 不再把 Excel 当作语义摄取链路的中心案例。
- 不再在该文档中描述任何内置模板映射或格式保留逻辑。
- 文件任务执行使用通用外部执行入口，优先由 `runner.ps1` / `runner.py` 接管。

## 8. 质量边界

本层质量由以下指标约束：

1. 不同文件类型具备明确解析策略。
2. SmartDocument 与 FileAsset 保持显式关联。
3. 分块、摘要、引用提示与前端状态保持一致。
4. 运行时控制信息不写入语义层。
