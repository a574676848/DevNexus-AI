# DevNexus AI 使用场景

![文件资产与语义聊天核心流程](../assets/Core_Flowchart.png)

## 典型场景

当前项目适合以下三类场景：

1. **开发与工程协作** — 代码理解、重构、排错、测试、架构梳理
2. **文档理解与知识整理** — 文档摘要、多材料归纳、交叉引用
3. **真实文件处理闭环** — 模板转换、批处理、自动化文件加工

## 开发与工程协作

### 阅读和改造现有代码库

系统结合聊天上下文、代码文件和结构化输出回答问题。复杂问题可升级到 Swarm 上下文工作包协同链路，结果可回收到会话和 Artifact 体系中继续追问。

### 代码任务

适合代码实现、重构、排错、测试补充和架构梳理。系统强调低噪、结构化、工程化输出。

## 文档理解与知识整理

### 上传规范文档后做摘要与问答

文件上传后经语义解析，SmartDocument 进入聊天上下文，可在会话中继续追问和交叉引用。

### 多份材料整理成统一输出

支持多文件进入同一会话上下文，适合总结、归纳、对比和交叉引用。

## 真实文件处理闭环

### 根据模板文件生成结果文件

完整文件运行时流程：

1. 上传输入文件和模板文件
2. 形成 FileAsset
3. 创建 FileTask
4. 调用 runner.ps1 或 runner.py
5. 生成输出
6. 回灌为新的结果资产

### 批处理和自动化文件加工

平台负责文件资产、任务状态和结果回灌；外部 runner 负责具体格式和算法。结果可继续进入下一轮任务或对话。

## Swarm 适用范围

**适合：**

- 多步骤工程任务
- 需要分解和并行推进的复杂问题
- 需要监控执行状态和人工确认的任务

**不适合直接替代：**

- 普通聊天
- 简单文件处理
- 单步格式转换

Swarm 是复杂任务编排能力，不是所有功能的统一入口。

## 典型用户路径

### 路径一：理解内容

上传文件 → 解析 → 在会话里追问 → 得到结论

### 路径二：生成结果文件

上传文件 → finalize → 创建 FileTask → runner 处理 → 结果回灌 → 加入下一轮

### 路径三：复杂研发任务

聊天描述目标 → 进入 Swarm → 监控工作包拓扑与执行状态 → 获取结果并继续迭代
