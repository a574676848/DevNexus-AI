# DevNexus AI 用户指南

本文档只说明当前产品里仍可直接使用的主流程，帮助用户在聊天、终端、Swarm 与审计之间判断下一步动作。

## 基本使用路径

1. 打开聊天页面。
2. 输入问题或任务目标。
3. 如需文件上下文，上传文件。
4. 等待文件进入可用状态后再发送消息。

## 运行态主路径

DevNexus AI 的主入口仍是聊天，但长任务不应只停留在聊天正文里。用户处理复杂任务时按以下路径判断：

1. 先看聊天主界面的状态摘要，确认工具是否失败、终端是否等待输入、Swarm 是否进入工作包协作模式。
2. 如果命令仍在运行或等待 stdin，进入终端面板查看命令、工作目录、退出码、归档状态和下一步动作。
3. 如果任务进入 Swarm，进入 Swarm 面板查看当前阶段、阻塞原因、失败工作包和可重试动作。
4. 如果需要复盘失败原因，先查看审计详情；维护者再按问题类型查询 `[AI.Prompt.Diagnostics]`、`[AI.Memory.ReplayEvaluation]` 或 `[AI.Swarm.Review]` 结构化日志。不要把这些内部事实当成普通用户主界面信息。

主界面只保留用户需要立即处理的信息：失败工具、失败原因、建议动作、等待输入、终端接管状态和可继续入口。成功步骤数量、事件总数、最慢工具耗时和 Prompt 诊断指标属于维护者排障信息。

## 上传后会发生什么

系统会把文件处理拆成两条链路：

- 语义链路：用于摘要、引用、检索和上下文注入。
- 执行链路：用于把真实文件交给任务工作区和外部 runner 处理。

这两条链路可以同时存在，也可以只走其中一条。

## 如何理解文件状态

### 语义上下文
文件被成功解析后，可进入模型上下文，用于阅读、总结、引用和问答。

### 执行上下文
文件作为真实资产参与任务执行时，会进入执行上下文。这里强调的是文件本体可被处理，而不是模型是否已读懂内容。

## 文件任务如何运行

当前文件任务运行方式为：

1. 建立任务工作区。
2. 准备输入文件与模板文件。
3. 生成任务合同。
4. 优先运行 `runner.ps1`，其次运行 `runner.py`。
5. 收集输出并回灌为新的文件资产。

## 如何继续处理结果文件

结果文件可以重新加入当前会话，继续作为下一轮输入。

## 如何理解失败状态

- 解析失败：优先看附件与输入区里的失败原因。
- 任务失败：优先看任务状态、失败摘要和是否可重试。
- 终端等待输入：优先进入终端面板发送 stdin，不要重新发起相同命令。
- Swarm 工作包失败：优先看失败工作包、阻塞原因和可重试动作，再查看执行报告。
- 审计或诊断异常：产品化审计只看工具失败、失败原因、建议动作、是否可重试和是否需要人工介入；Prompt 成本、记忆回放效果和 Swarm 复盘事实分别进入维护者日志 `[AI.Prompt.Diagnostics]`、`[AI.Memory.ReplayEvaluation]` 与 `[AI.Swarm.Review]`。
