# 常见问题 - 概念与设计

## 什么是当前项目里的两条文件主线？

当前文件相关能力分成两条线：

1. 语义主线
   - 负责把文件内容转成 SmartDocument。
   - 用于摘要、检索、引用和提示词上下文。
2. 文件运行时主线
   - 负责保存真实文件、创建 FileTask、调用外部 runner、产出新文件。

如果你需要“生成一个新的真实文件”，应该走文件运行时主线，而不是只依赖 SmartDocument。

## 为什么文件解析成功不等于生成了新文件？

因为解析成功只说明系统已经理解了文件内容，能够把它作为语义上下文使用；它并不代表平台已经执行了真实文件变换。

真实文件处理必须通过 FileTask 发起，并由外部 runner 在任务工作区中完成。

## 为什么上传后还要再创建 FileTask？

上传完成后只会得到 FileAsset。FileAsset 表示“文件已经进入平台并可被引用”。

只有创建 FileTask，平台才会：

1. 整理输入文件和模板文件。
2. 生成任务合同。
3. 调用 runner。
4. 收集 outputs 并回灌结果资产。

## SmartDocument 和 FileAsset 有什么区别？

- SmartDocument 是语义派生物。
- FileAsset 是真实文件资产。

前者适合拿来读、搜、引用和生成提示词；后者才适合做复制、转换、导出、模板套用和二次处理。

## 平台还内置 Excel 模板转换逻辑吗？

当前主平台已经不再把 Excel 模板转换这类特化逻辑内建在平台层。

现在的方向是：

1. 平台提供统一文件资产和任务运行时。
2. 具体格式处理由 runner.ps1、runner.py 或其他外部执行器负责。

这样可以避免平台代码长期绑死在某一种格式上。

## 支持哪些文件类型？

平台层对文件类型保持通用设计，不再只围绕某一类格式展开。

常见输入包括：

- PDF、Word、Markdown、文本
- Excel、CSV 等表格文件
- 图片
- 代码文件
- 其他二进制附件

是否能被“语义解析”与是否能被“真实处理”是两个独立问题，最终取决于解析链和外部 runner 是否支持。

## 文件安全吗？

平台通过以下方式保障文件隔离：

1. 上传进入统一文件资产平台。
2. 运行时在受控工作区内执行。
3. 用户之间文件与任务上下文隔离。
4. 结果回灌后继续按资产管理，而不是散落在任意目录。

## 可以只上传文件不做解析吗？

可以。

上传和语义解析不是强绑定关系。你可以只把文件作为 FileAsset 存入平台，再直接拿它去创建 FileTask。

## 可以只做解析不做文件处理吗？

也可以。

如果你的目标只是让智能体理解内容、引用内容、对内容总结或问答，那么只走 Artifact parse 和 SmartDocument 链路就够了。

## 当前推荐的文件处理扩展方式是什么？

推荐方式是实现外部 runner：

1. runner.ps1
2. runner.py
3. 可扩展到 opencodecli 等外部执行器

平台层负责调度、校验、回灌和 UI 状态；格式特化逻辑由执行器负责。
