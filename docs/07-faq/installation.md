# 常见问题 - 安装与启动

## 本地开发最低需要什么？

建议至少具备：

1. .NET 10 SDK。
2. PostgreSQL。
3. Redis。
4. 对象存储或本地存储配置。
5. 至少一个可用的 LLM 供应商配置。

如果你要联调搜索或完整体验，再补齐 Qdrant、Seq、Elasticsearch。

## 一定要用 Docker 吗？

不是硬性要求，但强烈推荐。

原因很简单：当前系统依赖不止数据库，还包括 Redis、向量库、日志和搜索服务。手工维护这些服务成本很高。

## 启动后端最常见的失败点是什么？

最常见的是这四类：

1. 连接串错误。
2. JWT 或加密密钥未配置。
3. Redis 或 PostgreSQL 未启动。
4. 数据库迁移未执行。

## 如何快速判断是依赖服务没起来，还是代码本身有问题？

优先这样判断：

1. 看后端日志里是否出现连接拒绝、认证失败、迁移失败。
2. 单独确认 PostgreSQL 和 Redis 是否能连通。
3. 如果依赖都正常，再看具体启动栈跟踪。

如果错误一上来就是 Connection refused、timeout 或 authentication failed，通常先别怀疑业务代码。

## 文件上传相关的环境配置需要注意什么？

需要特别注意两层：

1. StorageController 用到的存储后端。
2. UploadSession finalize 之后的文件平台登记流程。

这意味着“存储服务可用”不代表“文件平台可用”；两者都通了，上传链路才算完整。

## 为什么上传接口能调通，但任务执行还是失败？

因为上传和执行不是同一层。

上传成功只说明文件进了存储并登记成资产；真正执行 FileTask 还依赖：

1. 任务工作区创建成功。
2. runner.ps1 或 runner.py 可用。
3. runner 依赖环境可执行。
4. outputs 目录产出有效结果。

## Python runner 需要额外安装什么吗？

如果你准备用 runner.py 处理文件，就必须保证运行环境中有可用 Python，并且所需依赖已经安装。

平台不会自动替你安装 pandas、openpyxl 或其他文件处理库。

## PowerShell runner 有什么前提？

需要运行环境能执行 PowerShell 脚本，并满足你脚本内部依赖的模块或命令条件。

如果平台检测到 runner.ps1，会优先执行它。

## 如何排查数据库迁移问题？

建议顺序：

1. 确认数据库实例能正常连接。
2. 检查连接串是否指向正确库。
3. 手动执行迁移命令。
4. 查看是否存在权限不足或模型变更冲突。

## SignalR 连不上时先查什么？

先查：

1. API 服务是否已正常启动。
2. Redis 是否可用。
3. 前端连接的 Hub 地址是否正确。
4. 认证 Token 是否有效。

当前正确的 Hub 路径是：

- /chat-hub
- /artifact-hub
- /swarm-hub

## 最推荐的本地启动方式是什么？

最推荐的是使用 AppHost 或项目内既有的整体验证方式，把依赖服务和主应用一起拉起，然后再单独验证：

1. 登录是否正常。
2. 聊天是否能流式返回。
3. 上传是否能 finalize。
4. FileTask 是否能调用 runner 并产出结果。

如果这四步都通过，当前本地环境就已经具备继续开发和联调的基础条件。
