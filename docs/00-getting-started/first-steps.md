# 第一步：理解产品能力边界

完成快速开始后，建议先了解系统的能力结构。

## 聊天是统一入口

聊天不仅负责发送文本，也承担文件上下文、任务状态和结果继续处理的入口职责。

## 语义链路和文件链路

### 语义链路

- 上传后可触发解析
- 解析结果用于摘要、检索、引用和上下文增强

### 文件链路

- 上传完成后形成文件资产
- 基于文件资产可创建文件任务
- 文件任务会在工作区中调用外部 runner 处理真实文件

## 标准使用流程

1. 上传文件
2. 完成上传确认
3. 得到文件资产
4. 需要内容理解时，走语义解析
5. 需要真实处理时，创建文件任务
6. 将结果重新加入下一轮

## 失败信息可见

界面会暴露解析失败和任务失败原因。链路不通时，先看失败信息，再看日志和接口状态。

## Swarm 的定位

Swarm 负责复杂任务编排，不是所有流程都必须经过的中间层。简单对话、文件解析和文件任务可以直接完成。
